## What's new in 1.0.31

### New
- **Input Tester**: a separate program that shows what a game sees through HidHide
  - Opens from Tools › Viewers › Input Tester… or the HidHide page, and is installed next to the program
  - Shows your sticks, Xbox pads and other game devices live (axes, buttons 1-128, hats 1-4) and selects the stick you move
  - Compares what it sees with what Gremlin expects and gives a plain answer: "✓ Pass: programs see only what they should" or "✗ Problem", with the fix for each problem
  - Warns when Steam can see your sticks and says how to stop it
  - A Logs tab shows the tester's own log, Gremlin's logs and the DirectInput reader's log; Save Diagnostics includes them
  - Tells you to restart it when HidHide's settings changed after it started
- **Reset Devices** on the HidHide page restarts the ticked USB game devices so every program opens them again (HidHide only checks a device when a program opens it)
  - Lists your physical USB game controllers, with the hidden ones ticked; asks for administrator rights once for all of them
  - Shows each result: reset and how long until it was back, needs a Windows restart, not found, and so on
  - The list follows plugging and unplugging while the window is open, and a device that comes back later shows "back ✓ (plugged back in)"
  - Xbox pads aren't ticked by default: they can't be restarted live, so unplug them and plug them back in
- **Trace** (Debug › Live Log Reader › Trace, and Debug › Tracing): follow chosen sticks or single controls from the stick to vJoy
  - Each move shows what the stick sent, what the profile did with it, and what was written to vJoy (or why it was blocked), plus device, Start, Stop and mode change lines
  - Map to Mouse is shown too: one line per change of speed or direction, and per button press or release
  - Warns when a stick moves but nothing reaches the program, or vJoy shows something other than what was written
  - Can trace HidHide too, and warns when a traced stick isn't on HidHide's hidden list
  - Options ▾: how many axis lines per second, the trace file's maximum size, and Clear Trace File…
- **OSC** grows into a full built-in device
  - OSC inputs live in their own file shared by all profiles, like the Logical Device; older profiles' addresses are moved over automatically
  - Per-input settings: Button, Trigger on message, Axis with a range, Change, Message + data, Source
  - OSC Monitor (OSC page › Monitor, or Tools › OSC Monitor): the last 200 messages in and out, with Pause, filter and Add as Input…
  - A new **Send OSC** action, two-way feedback (send modes, vJoy values and Logical Device controls back out), encoder mode, a list of targets, and finding other OSC devices on the network (off by default)
  - Setup is in OSC's Module Setup, in tabs; helpers for Bitfocus Companion (Add Companion target, Companion feedback rows, Copy for Companion)
  - Stop releases any OSC button still held
  - A new OSC chapter in Help
- **Logical Device** stands alone: one shared layout in its own file, used by every profile
  - Actions, conditions, macro steps and script variables keep pointing at the right control even after another is deleted
  - Older profiles' controls are moved over automatically, with a note listing what moved and a backup of the old file on first save
  - Logical Device card: Add Image… and Remove Image
- **Recovery copy**: while a profile has unsaved changes a copy is kept about every minute; after a crash you're offered Restore, Discard or Not now
- **Merge Axis** has a new operation, **Maximum Deflection**: the axis furthest from centre wins
- A **Device Library** button on the toolbar of every page

### Changed
- New actions start somewhere useful
  - A new Map to vJoy starts on the first claimed vJoy output not yet used in this mode
  - New vJoy macro steps and conditions start on the first claimed vJoy output
  - New button checks and button and key macro steps start on Pressed
  - The vJoy output list only offers outputs the vJoy device really has
  - A new Merge Axis or Dual Axis Deadzone starts on a named one ("Merge Axis 1")
- Mouse motion from Map to Mouse was reworked
  - Motion from several inputs adds up, each button or hat speeds up on its own, and speeds are delivered as set
  - Motion stops on a mode change that doesn't use it, on Stop and on Pause
- Keys
  - Win keys count as modifiers; modifiers (Shift, Ctrl, Alt, Win) are always pressed first
  - A recorded key combination keeps the order you pressed the keys in
  - Script keyboard variables work with numpad and other extended keys
- A macro step that can't be read no longer stops the profile opening: it is kept as it was, does nothing when run, and the editor says so
- Run Command reports a program that can't be started once in the log
- Reference lists actions on keyboard keys, and never offers an input's Root
- Devices are told apart by their Windows id, never by name: twin sticks and twin Xbox pads are no longer mixed up (Device Library, Device Pack, Auto Mapper, HidHide check, Input Tester)
- HidHide page
  - Plainer wording, with help on turning HidHide off and on and why Gremlin always sees its own devices
  - The last Input Tester result is shown as **Last Status** on its own line, with a note when HidHide changed after the test
  - Warns when a game or the Input Tester was started before the last HidHide change
- The DirectInput reader is updated, and its licences ship with the program
- Every delete, remove or clear asks the same clear question, with a red button named for the action
- Choosers open in the last folder you used for that kind of file
- Title bars start with the program name and version
- Logical Device loops can't hang the program: a control can't map to itself, and a chain is stopped after 8 steps with one warning

### Fixed
- An Xbox pad that switched layout no longer gives "Invalid axis 3"; a device that changes layout is treated like unplug and plug back in
- A profile no longer fails to start because one control of a device can't be read; that control is skipped and logged
- Closing the program no longer waits 5 seconds
- No false "out of step" warning in Trace after Stop
- A Cubic Spline now passes through its points
- Saving a macro keeps a Logical Device step whose control is missing
- Reset Devices could restart a stick but show "failed: no result"
- The Input Tester's buttons area fills the window, and with Follow input on a pressed button scrolls into view
- Split Axis, Dual Axis Deadzone and Send OSC editors stay inside the pane, so Add Action is no longer cut off
- Device Library Restore works for Keyboard, OSC and Logical Device
- Clear History works even after a Device Library window was closed
- Home cards resize by their grips instead of scrolling the page
- Tool windows reopen fully on screen with mixed-DPI monitors
- Module Setup and Calibration say clearly why a change wasn't saved

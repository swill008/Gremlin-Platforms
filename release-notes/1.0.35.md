## What's new in 1.0.35

### New
- **Search, rebuilt: type to find anything in every profile.** One search box finds keys, actions, names and outputs across every profile in your profiles folder, the open profile (marked **(open)**, unsaved changes included) and the Device Library's saved setups, and says in which profile, on which device, in which mode and on which input each one is. It is its own window (toolbar magnifying glass, Tools › Mapping › Search…, Ctrl+Shift+F); opening it again brings it to the front
  - Results show as you type. Matching is forgiving: the letters you type, in order (`gr tog` finds "Gear toggle"), with exact and start-of-word matches first and the matched letters lit
  - **Aa** (Match case), **ab** (Whole word) and **.\*** (Regular expression) beside the box, all off at first; **?** lists the prefixes
  - Prefixes narrow a search to one field: `key:`, `vjoy:`, `xbox:`, `osc:`, `mouse:`, `mode:`, `profile:`, `device:`, `action:`
  - Results are grouped by profile, then device, with counts and sortable **Input**, **Mode** and **Action** columns; **Fold all** / **Unfold all**
  - The sidebar: **Look in** (**All profiles**, **This profile only**, **Device Library**), **Show** (**Keys**, **Actions**, **Names**, **vJoy**, **Xbox**, **OSC**, each with its count), **Health** (**Used twice**, **Binding output not found**, **No bindings**, **Not plugged in**) and **Recent** (your last 10 searches)
  - **Listen**: press a stick control or a keyboard key, or send an OSC message, and Search looks for it (**Heard: <input>**); Esc stops. When **Listen for OSC messages** is off, Search says so and still hears sticks and keys
  - Text you typed into an action (a note, spoken text, a command line, a sound file, a label) is searched too, and shown under **Notes** in the detail pane
  - A binding a mode inherits is found in every child mode that uses it, tagged **Inherited from <mode>**; **Used twice** counts it
  - Click a result, or press Enter on it, to open it: in the open profile it goes to that device, mode and row; in another profile it asks to save your changes first, then loads that profile and goes to the row; a Device Library result opens the Device Library on that setup. A device with no input module says "<device> has no input module, so its bindings can't be shown here." with **Open Device Mapping Editor**
  - The detail pane shows the whole binding, the mode chain it comes through and, for **Used twice**, the other inputs sending to that output. Right-click a result for **Open**, **Open in Device Mapping Editor**, **Copy as text** and **Search for this target**
  - Keyboard: Up / Down move, Enter opens, Esc clears the box, Esc again closes the window
  - When nothing is found, Search says what it looked for and where, offers **Did you mean <word>?** and one-click fixes (search all profiles, turn off a toggle, clear filters). A profile it could not read is listed with the reason
  - Search remembers its size and place, the last search, Look in, the filters, the toggles and the detail pane
  - **Suggestion list while typing** (a list of words and recent searches under the box) is there but off at first; turn it on in Search's settings
  - Saving a profile updates its results straight away
- **Find uses…** (right-click on a row, a vJoy Viewer chip, an Xbox Output View row or a mode in Manage Modes) now opens Search with the text filled in, e.g. `mode:Combat`, and searches at once
- **Search this device** on a Home card's right-click menu opens Search for that device

### Changed
- **Every action knows what it uses.** Each action, macro step and condition now says for itself which inputs, outputs and modes it points at, and one part of the program answers "who uses what" for everything that asks: Search, Binding output not found, the Xbox pads in use, the vJoy Viewer, Driven by, the Xbox Output View and the row details. A new action is found everywhere as soon as it says what it uses. Because of this, Search also finds Send OSC targets, Map to Mouse, Load Profile, and the axes Merge Axis and Dual Axis Deadzone read
- The old Search pickers (Input / Output / Mode / Action type, results grouped by kind of use, ‹ Previous / Next ›) are replaced by the search box

### Fixed
- Reliability work: a test that left device names behind could rename a folder in a later test; each test now starts clean. The release build uses the newer GitHub release step, so it no longer warns about Node 20

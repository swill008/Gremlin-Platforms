## What's new in 1.0.32

### New
- **Can't be sent**: a binding the program can't send is marked in red everywhere
  - Map to vJoy, Map to Xbox, Map to Logical Device and Send OSC show a red **⚠** on their target, with a tooltip saying why (for example "vJoy 1's Button 57 is not Found (vJoy 1 has Buttons 1–56).", "Xbox 360 Controller is not Found.", "OSC output is Off.")
  - The source device's Home card gets a red outline and "⚠ n bindings can't be sent", with a tooltip naming each input
  - Page rows show the ⚠, the Configuration page's wire labels turn red, and Find has a **Can't be sent** tick
  - The ⚠ is also checked in the Condition, macro and Script vJoy pickers
  - Every ⚠ stays current while editors are open: claiming outputs, saving a module, turning a vJoy on or off, changing OSC's settings or the Logical Device updates it at once, with no need to reopen anything
  - Opening a profile shows a notice (**Open Profile**) naming the devices with bindings that can't be sent, for example "VKBSim NXT: 94 bindings can't be sent. OSC: 1."
- **The OSC page is rebuilt** in the style of the Logical Device page
  - Rows with a settings line, groups and order, Find, a right-click menu (Change Address, Edit Settings on several inputs at once, Copy for Companion, Send Test), the shared action pane and page Undo
  - The OSC Monitor is docked at the bottom of the page, folded by default, with **Pop out**
  - Each row shows its live value and when it was last seen
  - Feedback rows sit on the OSC page under their input: **Add Feedback**, **Companion feedback** (**Key text**, **Key color**), and a group **Feedback not tied to an input**; the Feedback tab shows the list with **Edit on the OSC page**
  - The OSC layout and names are saved with the inputs at File › Save
  - A check of your Companion setup on the Output tab
- **More OSC**
  - Address wildcards (`/fader/*`, `?`, `[..]`, `{a,b}`): one input can answer many addresses; an exact address wins over a pattern
  - **Action state** as a feedback source: a Smart Toggle's on/off, Tempo's last press, and Running/Paused
  - Conditions (**OSC input…** in a Joystick condition), macros (an **OSC** step, and Record captures OSC) and scripts (**Choose an OSC input**, and sending to named targets) can use OSC
  - **Allowed senders** on the Server tab: only listed addresses are accepted; a message from another sender shows in the Monitor as **blocked**, with **Allow this sender**
  - Axis inputs: an **Invert** box on the row, and **Shaping** (**Deadzone low:** / **Deadzone high:**) in Edit Settings
  - Encoder **Acceleration:** Off, Low, Medium or High
  - Add Inputs › **From TouchOSC Layout…** creates inputs from a .tosc file
- **OSC always listens**: while "Listen for OSC messages" is on, the port opens at start-up and stays open whether the profile is running or stopped; quitting closes it
- **OSC tracing**: the Trace tab has an **OSC** row with **Receive**, **Inputs**, **Output**, **Feedback** and **Setup and files**
  - A line at every step, and a **BLOCKED** line with the reason for every message dropped or send refused
  - A busy address is written at the Axis lines rate with "(N messages between)"; the same error is shown at most 10 times per Run, then stays quiet
  - What an OSC input's actions send to vJoy or the mouse is traced too
- **Configuration and Keyboard pages rebuilt** in the Logical Device style
  - Claimed rows, Find with Type and Output filters, groups and order, the right-click menu, the shared action pane and one Undo
  - Live lights and bars, and a jump to the input you press
  - Groups, order and names are saved at File › Save
  - **Clear Name** in the Configuration page's row menu
- **Each list page has its own Appearance** (Configuration, Logical Device, Keyboard, OSC), on the page bar and in the right-click menu, with row alignment, width and space between groups
- **List pages follow your presses**: the Logical Device, Keyboard and OSC pages tint the row you press and jump to it, with axis and fader bars; hats are followed too, and a quick tap still shows

### Changed
- **Names and bindings stay current everywhere at once**
  - Home cards and the Configuration page title show the name you gave the device
  - Renaming or forgetting a device updates the Device Library, the device strip, the viewer lists and the input names inside editors
  - "Driven by" on Home cards, the Output View header, the viewers, Button Map labels and the Xbox page follow every change: actions, modes, Undo, the OSC page and the Logical Device
  - Device Library **Swap with Another Stick…** and **Change vJoy Output…** now update every screen
  - Logical Device names follow in the Input Viewer, the Xbox page and the OSC page, including controls a script creates; the OSC Feedback list shows Logical Device controls not yet saved
- **Editors fit a narrow pane**: Map to vJoy and Map to Logical Device put the picker above their options with "Invert activation" on its own line, and the axis row wraps; the vJoy boxes are never narrower than their widest choice. All editors, and the action title and Root rows, fit the pane at its minimum width and at 150 % and 200 %
- The Script settings row gives way so the vJoy picker fits
- **Send OSC keeps its target's name**, so a missing target says "OSC target <name> is not Found."
- Opening another input while the pane has unsaved changes asks Save, Discard or Cancel
- Clear on the Configuration page's Find bar also resets Type and Output
- The Appearance panel closes when the window gets too narrow
- The Button Map's "Autosave" option is now **Recovery copies**
- HidHide busy now says "in use by another program"; Listen names the program holding the OSC port
- Help was checked against the program in every chapter: the OSC chapter is rewritten, and the Configuration and Keyboard pages, held layouts, the Input Tester, Device Pack limits, recovery copies and the loop guard are covered, with Show me links throughout

### Fixed
- A held Logical Device button is no longer left on (or released twice) after a mode switch
- Switching a Map to vJoy action to another vJoy really moves it
- A vJoy that is turned off is listed "(not available)"; picking it saves a valid binding, and writes to it are blocked and logged once per Run
- The vJoy Viewer lists and lights OSC and Logical Device bindings
- The red ⚠ box is always wide enough for its text
- Logical Device and OSC rows that can't be read are kept and shown, not dropped
- Module Setup saves only its own names; empty keys are kept; a save names the file that failed
- Damaged Device Library rows and Device Packs are refused instead of loaded
- Adding an OSC input that already exists selects it
- A bad incoming OSC wildcard, a TouchOSC refusal or a missing condition input no longer causes an error trace
- Key names no longer depend on which lookup ran first ("a" vs "A")
- Reliability: the program no longer sends output outside a Run, quits cleanly, and avoids several rare hangs and leaks

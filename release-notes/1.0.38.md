## What's new in 1.0.38

### New
- **Screen Saver Mode** (Tools › Screen Saver Mode…). Some devices, such as flight sticks and throttles and some USB microphones, send reports to Windows many times a second even when nobody touches them. Windows counts that as someone using the PC, so the screen saver and display-off never happen, a burn-in risk on OLED screens. Screen Saver Mode keeps its own idle time from your keyboard and mouse only, with two timers: one starts the screen saver, the other powers off the displays
  - Off until you switch it on; it remembers
  - **Screen saver** and **Power off displays** each have their own switch and wait (both on at first), for example the screen saver after 5 minutes and the displays off after 15. Each wait shows Windows' own time and follows it when you change it in Windows; type your own time to use that instead, clear it to go back to Windows'
  - Keeps the displays off: the same devices make Windows switch the displays back on a split second after they power off, so Gremlin-Platforms powers them off again (at most once a second) until you press a key or move the mouse, and shows how many times Windows turned them back on. OLED panel maintenance still runs while they are off
  - Holds off while a full-screen program is in front (can be switched off), while a program such as a video player keeps the display on, and while the PC is locked
  - Keys and mouse movement sent by other programs (for example remote control) count; keys and mouse input sent by Gremlin-Platforms' own bindings don't
  - **Refresh Devices** lists the devices that never go quiet and keep Windows awake
  - **Refresh Programs** lists the programs, drivers and services keeping the display on, and **Refresh System** the ones keeping the PC awake, each row with an **Ignore** switch (both ask for administrator rights)
  - Works only while Gremlin-Platforms is open
  - For problem reports: a **Screen Saver Mode** tick on Debug › Tracing records the countdown, holds, each scan and the exact Windows commands and answers; errors always go to the log

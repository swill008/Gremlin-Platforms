## Failures (one paragraph each: row, spec ref, what happened, file:line of the likely cause, suggested fix)

**S73 (07 S73, AU-112): chips don't follow an action edit.** With the map showing Action, changing button 2's Description text through the action pane's model, and adding a Description to button 3 through the pane's Add Action slot (`appendAction`), left the chips at their old text ("Gear up", nothing for button 3) for 3 s and longer. They updated only when something later emitted `signal.profileChanged`. Likely cause: `HardwareProfile` refreshes chip labels only on `signal.profileChanged` and `signal.modesChanged` (`gremlin/ui/hardware_profile.py:924-925`). Action edits send `signal.inputItemChanged` (`gremlin/ui/action_model.py:58-62`, from `appendAction`, `dropAction` and `removeAction`), and a property edit such as a description text sends only its own model signal (`action_plugins/description/__init__.py:90`). The Button Map does not listen to either. Suggested fix: have `profileLabelsChanged` follow `signal.inputItemChanged` and `signal.actionsChanged` too. For property edits inside an action (text, keys, vJoy target), the program needs one "an action's data changed" notice that the action models send and the Button Map listens to (debounced). Write the failing test first, driving `DescriptionModel.description` and `appendAction` with the window open.

**S80 (07 S80; test plan hands-on "Export to a read-only folder says why"; compare Q19/S91 "as Template export does"): Template export failure gives no reason.** Exporting a template to a read-only file, and to a folder that doesn't exist, both say only "Could not write My Layout to that file.", with no file, folder or reason. The S80 text ("saying when rename or export fails") is met word for word. The test plan's hands-on step, and Q19/S91, which treat Template export as the model that names the file and the reason, are not. Likely cause: `qml/DialogJoystickButtonMap.qml:2626-2627` uses a fixed message, and `HardwareProfile.exportTemplate` (`gremlin/ui/hardware_profile.py:1725`) returns only a bool. Suggested fix: give template export the same `export_failure(path)` text that the map export uses (`hardware_profile.py:1016`; for example an `exportError()` after a False). Rename failure has the same fixed text (`DialogJoystickButtonMap.qml:2563`). The lead should decide whether this is a gap or a test-plan wording issue.

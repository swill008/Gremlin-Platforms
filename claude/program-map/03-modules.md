# Input and output modules

Mapped read-only against the code on 6 Oct 2026 (after 4f6bdfa4). Line numbers drift; re-check them before a step starts. "CONFIRMED" below means seen in the code (not run in the app) unless a test is named.

## 1. Purpose

Every device has a module file that says which of its controls the program may use (its claims), their friendly names, its picture, calibration and page Appearance. Input modules decide what reaches your actions; output modules (one per vJoy) decide what reaches the driver; the Xbox output passes everything. This subsystem is also Home (the device cards), Module Setup, Calibration, the Output View, Delete Device, Start Fresh and module import.

## 3. What it owns

**Files (data folder)**
- `modules\<Device Folder>\` (from 2026-10-11, D-03-DEVICE-FOLDERS, S128-S133): one folder per device, named after its shown name (S130, S132), holding `device.json` (its id and shown name; the lookup is by this id), `module.json` (the module file), `recovery.json` (the Device Mapping Editor's recovery copy), `pictures\` and `imported\`. Templates live in `modules\templates\<name>\`; a window's unsaved pictures in `modules\cache\` (the edit). Owned by `gremlin/modules/store.py`; the old layout is moved once by `folders_move.py` (ONE-TIME, OT-1, S134), which writes `modules\folders.json` (and `folders-move.state` while it runs) and a backup in `<data folder>\backup\<date> device folders move\`.
- `modules\<Device Folder>\module.json` (was `modules\<slug>.json`): one module file per device. Keys this subsystem writes: `kind`, `device`, `direction` (`source`/`dest`), `boundName`, `boundGuidLocal`, `claim`, `image`, `calibration` (per axis id: low, centerLow, centerHigh, high, withCenter), `view` (Output View Appearance), `layout` (Device Bindings and Keyboard groups and order, written at File › Save through `store.save_pending`, 05 S122, S122a); the old `catalog` key (Device Bindings Appearance) is gone from 2026-10-10 (batch C: each list page's Appearance lives in program settings, 05 S125, AP2), and defaults `space`, `pageW`, `pageH`, `photoWell`, `nodes`. The Device Mapping Editor also writes this file (`nodes`, `ui`, `image`).
  - Writers in this subsystem: `DriverInputModel.saveClaim` (module_model.py), `saveViewConfig`, `store.save_pending` (Device Bindings/Keyboard layout and friendly names, at File › Save; `saveCatalogConfig` removed 2026-10-10), `calibration.write_axes`, `auto_mapping_tool.merge_claim_into_output`, `store.import_file` / `undo_file_import` (from 2026-10-11; were `import_module_file` / `undo_last_import` in hardware_profile.py), Module Setup's Import Image and Save (`keepPhoto` keeps the picture in the edit, `saveClaim` -> `store.commit_edit` writes it and the claims in one write, S52).
  - `module_file.write_bytes` (the safe write): from 2026-10-12 (batch G, to-do 104) the temporary file uses the Windows extended-length form when the path is near 260 characters; a final path over 260 characters is still limited (10 gap LONG-PATH).
  - Other writers (other subsystems): Device Mapping Editor save / saveUi / restorePhoto, Device Pack, History Restore.
- `modules\<Device Folder>\pictures\photo.*` (was `modules\<slug>\photo.*`): the device picture, and every other picture its device map names (`pictures/<file>`); never shared between devices (S133). (`modules\library\` is no longer written; the move archives it into its backup.)
- `modules\<Device Folder>\pictures\device-image.<ext>` (from 2026-10-12, D-03-DEVICE-IMAGE, S137): an input module's device image, named by the module file's `deviceImage` key; written only through `store.set_device_image` / `remove_device_image` (Home card menu via `ModuleListModel.setCardImage` / `removeCardImage`; Module Setup Save via `DriverInputModel.saveClaim(..., image, removeImage)`).
- `modules\<Device Folder>\imported\`: the previous file kept by an import (S58; was the shared `modules\imported\`). The "Import from" list names the other devices' folders (`store.import_choices`).
- `modules\<Device Folder>\module.json.bad-<date>`: a damaged file moved aside by Start Fresh.
- Deleted devices folder (`util.deleted_devices_dir`, setting `deleted-devices-folder`, default `deleted devices` in the data folder): `<stem> <date time>.json` from Delete File; `<name>\<name>.<stamp>.zip` packs from Delete Device.

**Settings (configuration.json)**
- ~~`global/internal/module-file-bindings`~~: removed 2026-10-11 (D-03-DEVICE-FOLDERS, S1, S94): no file bindings; the id in each folder's `device.json` does their job. Still registered and read once only by the one-time move (`folders_move.register_setting`, `old_bindings`; ONE-TIME, OT-1) until OT-1 is removed.

Options' "Reset all card sizes" goes through `CardSizes`.
- `global/internal/twin-device-names`: written by device start-up (device_initialization), read here indirectly through device names.
- Legacy calibration in program settings (`Configuration().get_calibration`): read only, used until the module file has a curve.

**In memory**
- `registry._cache` (path -> Module, by file time and size).
- `InputModuleRuntime._claims`, `_dest_guids`, `_passthrough` (replaced whole on each reload).
- `output._vjoy_claims`, `_vjoy_names`, `_vjoy_modules`, `_xbox_modules` (1 s cache, under `_lock`); `_blocked`, `_vjoy_failed_at`, `_told_busy`, `_vjoy_off` (turned-off vJoys, VJ1b), cleared at `reset_drivers`.
- The can't-be-sent texts (D-05-CANT-SEND, D-05-CANT-SEND-ALL): owned by `output.py` (`cant_send_text`, `cant_send_words`, `cant_send_bindings`; each action's `references()` carries the text as `Reference.why`) and never stored; every reader (picker, editors, page rows, Find tick, Home card, wire label, load notice) asks it.
- `store._import_undo` (was `hardware_profile._import_undo`): the Undo record for the last Module Setup import, tied to the device and the window (`can_undo_file_import(device, guid, window)`).
- `store._index` (device id key -> folder, under `_dirs_lock`; rebuilt when folders change, `_dirs_changed`).
- `ModuleListModel`: rows, focus, last line per card, hidden names, claim cache per card (0.5 s), vJoy target cache, output snapshot.
- `DriverInputModel`: the open device's rows, Undo/Redo (100 steps), "not connected" reason.
- `AxisCalibration`: per-axis limits, capture state, Undo/Redo (100 steps, merged within 1 s).

**Who else may change them**: the Device Mapping Editor, Device Pack and History Restore write module files directly (see system-maps map 1, part B). Nothing else writes the Home settings or the binding store.

## 6. Threads and timers

- No threads are started in this subsystem.
- Events: stick events come from the DILL callback thread and key events from the keyboard hook. `InputModuleRuntime` is a QObject on the main thread, so its `_on_hid` / `_on_key` run there (queued). Module Setup connects raw events with `QueuedConnection` explicitly (module_model.py:1758-1764).
- `device_change_event` is emitted on the "device list update" timer thread (event_handler.py:388-419); every receiver here is a QObject method, so it runs queued on the main thread.
- `output.py` is called from whichever thread runs an action (event thread, macro and timer threads). Its claim cache is under `_lock`; its blocked-log and busy-vJoy state are not.
- Qt timers (main thread): `ModuleListModel._reload_timer` 200 ms single shot; `_refresh_timer` 50 ms single shot; `_dest_timer` 50 ms repeating, always on (does nothing while stopped); `StatusPage` split timer 150 ms; `DeviceLiveState` 33 ms timers (Output View).
- Time: `output.py` (`time.monotonic` for the 1 s claim cache and 3 s vJoy retry), `module_model.py:1500` (0.5 s claim cache), `device.py:1242` (1 s Undo merge), `module_file.start_fresh` and `hardware_profile` stamps (`time.strftime`, `datetime.now`). None go through `gremlin.clock` (which has no monotonic clock).

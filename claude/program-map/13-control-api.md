## 1. Purpose

During the 2026-11-22 display-wake investigation, reading Screen Saver Mode's
wake count, whether a profile ran, and turning tracing on all needed outside
scripts or the user. Control from other programs lets the user, other users,
scripts and Claude read the program's state and control it from the same PC:
the `gremlin-ctl` command line, and a development-only MCP server for Claude
Code. It is off until the user switches it on in Options.

## 6. Threads and timers

| Thread or timer | Started by | Does | Ends |
|---|---|---|---|
| The listener thread | `control_api` through `gremlin.threads`, only while the switch is on and the program runs | accepts one connection at a time, reads requests, runs handlers; bounded waits; never blocks the main thread | switch off or quit (bounded stop) |
| Main-thread calls | `gremlin.threads` main call from the listener thread, bounded by the call's `timeout_s` (10 s; 30 s for profile.load and window.screenshot) | runs `main_thread=True` handlers (commands, windows, profile, options) and the Run / Stop request of run.start / run.stop (S24) | on return, or on timeout the reply is an error and the program carries on (S9) |

Off (S2): no listener, no thread, no endpoint file.

## 7. Rule breaks

None planned. Layer rule: calls use the program's own paths (Run / Stop, File, Options, the menu command list, tracing); nothing touches vJoy, ViGEm or hardware directly. Program thread rules: the listener runs on a `gremlin.threads` thread with bounded waits; the program never waits on the API (S9).

## 8. Behaviour spec

- **S1** **Three layers, one owner each.** (1) The API in the program: a private Windows named pipe with a secret key (the same method as the device helper); the key is written to a file in the user's Gremlin Platforms folder; it is the only part that touches the program. (2) The client library: one Python module that connects to the pipe and makes the calls, the only code that knows the protocol. (3) Front ends on the library: the command line `gremlin-ctl.exe`, shipped in the installer next to `gremlin_platforms.exe`, with a Help page; and an MCP server in the repo (`tools/gremlin_mcp/`), started by Claude Code from the project's `.mcp.json`, development only, its package a dev dependency, not in the installer. [decided 2026-11-23, user: shape agreed, 6a, 2a]
- **S2** **The switch.** Options › General, group **Control** (after vJoy), **Allow control from other programs**, off by default; its description: "Lets the gremlin-ctl command line and other programs on this PC read and control Gremlin-Platforms." Only the user changes it: the API cannot turn itself on or off (`option.set` on this key is refused). Local PC only. With the switch off, a client's answer says control from other programs is off, and nothing happens. [decided 2026-11-23, user: 1a, 5a]
- **S3** **What can be read.** The running profile, devices and whether each is plugged in, Screen Saver Mode's state and wake counts, the Health count, tracing on or off, and the last N log lines (system or trace). [decided 2026-11-23, user: 1c] [built 2026-11-23: `devices` lists the plugged-in devices, then the other devices the program knows (`store.known_devices()`), each with `plugged_in`] [test: `test_control_api.py::test_devices_lists_known_devices_that_are_not_plugged_in`]
- **S4** **What can be done.** Start and stop the profile; load and save a profile; tracing categories on and off; run any menu command by its id from the menu command list (`qml/main_commands.js`); read and change Options settings (except the switch, S2); window actions (S6). [decided 2026-11-23, user: 1c]
- **S5** **Commands come from the menu command list,** so a new menu command needs no API work. [decided 2026-11-23, user: design for change]

- **S8** **Every API action is written to the system log** as coming from the API: one line per call, "API: <call> <short args> -> ok" or "-> error: <text>"; a window press or type says "by API". The version handshake (`hello`, which the client sends before every call) is not logged, so one command writes one line. The line is "API: <call> -> ..." for a call with no arguments (no double space) or "API: <call> <args JSON> -> ...". An API version the clients check (`hello`, version 1). One call at a time; a 10 s limit (30 s for screenshots and profile loads), one limit covering the wait for a busy API and the call together, so the program always answers before the client gives up (S28); the program never waits on the API: a call that runs on the main thread and goes over its limit answers with an error and the program carries on. - **S11** **The command line** prints readable text, and raw JSON with `--json` for scripts. Exit codes: 0 done, 1 the call failed (also when the program stopped answering or closed during the call: "The program stopped answering; the call may have run."), 2 the command was typed wrong (an unknown command or option, a missing or bad argument; the usage text and "gremlin-ctl: error: <text>" go to the error stream), 3 version mismatch, 4 the program isn't running or control from other programs is off (it couldn't be reached at the start). No other code is used. With `--json`, an error also goes to the output stream as {"ok": false, "code", "error", "exit"}, the code being the program's (S25) or one of the client's own for errors that never got an answer: `not_running`, `control_off`, `version_mismatch`, `stopped_answering`, and `bad_args` for a mistyped command [client codes: user 2026-11-23, "keep them"]; the readable line still goes to the error stream. `help` and `--help` work while the program isn't running, with or without `--json`. Every error message says what to do next where there is a next step. [decided 2026-11-23, user: 2a; exit codes from the approved contract; usage code: user 2026-11-23, 1a, D-13-USAGE-EXIT, renumbered user 2026-11-23, 3a, 4a, 5a, D-13-RESEARCH] [test: `test_gremlin_ctl_cli.py::test_a_mistyped_command_exits_2`, `::test_bad_arguments_exit_2`, `::test_exit_4_means_not_running`]
- **S12** **The key.** While the switch is on and the program runs, the program makes a new random key and pipe name and writes them to `%USERPROFILE%\Gremlin Platforms\api\endpoint.json` (the user's Gremlin Platforms folder, not the movable data folder); switching off or quitting stops the listener and deletes the file. Protection: the pipe is made with Python's `multiprocessing.connection` (first-instance flag, so no other program can take the name; the key checked both ways by HMAC; JSON messages, never pickle). Known limits, recorded not fixed (CTL-PIPE-HARDENING): the pipe doesn't refuse clients from other PCs and keeps Windows' default permissions (the key still guards every call); gremlin-ctl opens it without limiting impersonation; the file's 0o600 mode has no effect on Windows, so the user's folder permissions protect it.

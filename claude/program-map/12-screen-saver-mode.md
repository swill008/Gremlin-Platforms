## 1. Purpose

Some devices (the VKB NXT throttle, the Maono PD200X microphone's consumer
control part, and other flight gear) send reports to Windows many times a
second even when nobody touches them. Windows counts each report as user
activity, so its idle clock never runs: the screen saver and display-off
never happen. That risks burn-in on an OLED monitor. Windows has no setting
to ignore a device for idle time, and hiding the devices with HidHide does
not help while any program (Gremlin included) reads them (study section 6).

Screen Saver Mode keeps Gremlin's own idle clock from the keyboard and mouse
only. It has two timers, each with its own switch and wait: one starts the
screen saver, the other powers off the displays and keeps them off while the
devices keep waking them. Real keyboard or mouse input ends the screen saver
or wakes the displays as usual (Windows does that itself).

## 7. Rule breaks

None planned. Layer rule: Screen Saver Mode reads only the keyboard and mouse through Raw Input and its own read-only HID scan; it sends no input and touches no output module or driver. Batch 5 (S21-S25): disabling and re-enabling devices is done only by the separate helper with administrator rights, only for HID device ids (`HID\…`) the journal lists (taken from the saved Devices list, S27), never a device the user disabled themselves; Gremlin itself never runs with administrator rights.

## 8. Behaviour spec

- **S1** **Tools › Screen Saver Mode…** (command `tools.screenSaverMode`) should open the Screen Saver Mode window. The item sits in the Tools menu's bottom group: OSC Monitor, **Screen Saver Mode…**, History, Options. [decided 2026-11-15, user: 17 a, 18 a]
- **S2** The window should have an on/off switch, **Screen Saver Mode**. While it is on, Gremlin keeps its idle clock whenever the program is open (a profile running or not, the window in the tray or not). Off, Gremlin does nothing at all and installs no hooks. It is off until the user switches it on, and remembers the choice. [decided 2026-11-15, user: 19 a]
- **S3** Gremlin's idle clock should restart on every keyboard key (down or up) and every mouse event (movement, buttons, wheel). Joysticks, gamepads, microphones and every other device never count. Keyboard and mouse input other programs send (for example a remote-control program) counts; input Gremlin sends itself (its bindings' keys and mouse) does not. [decided 2026-11-15, user: 2 b, 3 a]
- **S4** Two timers, each a row with its own switch and wait: **Screen saver** (starts the screen saver chosen in Windows; on at first) and **Power off displays** (turns every display off; on at first). Both count from the last keyboard or mouse input (S3), and the holds (S7, S11, S15) hold both. If both are on and the power-off wait is not longer than the screen-saver wait, the window says "Power off comes at or before the screen saver: the screen saver won't show." (both still work). [decided 2026-11-15, user: 15] [changed 2026-11-15, user: "lets do a timer that is editable between the screensaver and the off", 4 b; reverses decision 15 (D-12-SSM-ACTION); batch 4, built 2026-11-15] (was: **Action**: one choice, **Screen saver** (start the screen saver chosen in Windows) or **Power off displays** (turn every display off))
- **S5** Each timer's wait shows Windows' current time as the default: the screen saver wait for **Screen saver**, the current power plan's display-off time for **Power off displays**, each read again each time the countdown starts, so a change in Windows is followed without a restart. Windows' times are shown while Screen Saver Mode is off too (fixed 2026-11-15: it showed "never" while off, found when the user tried 1.0.38). A time the user types in a row replaces that row's Windows time and is used from then on until the user clears it; cleared, Windows' time is shown and used again. [decided 2026-11-15, user: 4, 16] [changed 2026-11-15, user: 4 b; batch 4, built 2026-11-15] (was: one **Wait time** for the one chosen action, Windows' time for that action)
- **S6** When the idle clock reaches a timer's wait, Gremlin should do that timer's action once per idle period (each timer on its own), then nothing more for that timer until keyboard or mouse input restarts the clock. Windows itself ends the screen saver or wakes the displays on that input. Power off keeps the displays off: after it fires, Gremlin listens for Windows' display state, and whenever Windows turns the displays back on without keyboard or mouse input it sends the power-off again, at most once a second; this ends on the next counted keyboard or mouse input or when Screen Saver Mode is switched off. Each re-send is traced (S16), and one line with the idle period's count goes to the normal log when keeping off ends. [changed 2026-11-15, user: 1 a; batch 4, built 2026-11-15; measured: SSM-POWER-OFF-WAKES] (was: When the idle clock reaches the wait time, Gremlin should do the chosen action once, then nothing more until keyboard or mouse input restarts the clock. Windows itself ends the screen saver or wakes the displays on that input. Constant device reports end neither (study section 6, tested 2026-11-15).)

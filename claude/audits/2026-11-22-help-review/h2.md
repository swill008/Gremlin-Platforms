# Help review H2: Home and devices, Options and profile

Reviewer: agent H2 (read-only), 2026-11-22.
Files: `qml/help/home_devices.js`, `qml/help/options_profile.js`.
Rendering: `qml/DialogHelp.qml` shows the body in a `TextEdit` with
`TextEdit.RichText` (Qt's rich-text subset): `<p>`, `<b>`, `<i>`, `<code>`,
`<h4>`, `<ul>`/`<ol>` (nested too) and simple `<table>` all render, so the
suggestions below use only those.

Counts: 17 high, 42 medium, 27 low (86 findings).

## Top 5 problems

1. **Walls of text inside one bullet.** Many bullets carry four or five ideas
   and run 50-110 words (home_devices.js:24, 44, 55, 83, 92, 291, 292;
   options_profile.js:44, 64, 134, 221). They read as paragraphs, not lists.
2. **Sentences that only make sense if you know the code.** "The card shows
   as picked first, as a click does" (home_devices.js:76), "the latest input
   the input module passed" (:40), "found by the device first and then by its
   name" (:305), "Its status and bus" (:37).
3. **Menu inventories instead of help.** The card-menu topic lists every
   item, then lists again which cards lack which items (home_devices.js:79-90);
   the same exclusion list is written out four times. A small table says it
   in a third of the space.
4. **Quoting on-screen text word for word in the middle of steps.** Delete
   Device step 3 (home_devices.js:116) and the Delete File bullet (:310) quote
   the whole dialog; the reader needs "confirm with the red button", not the
   dialog's start and end.
5. **Inconsistent names.** "Reset card sizes" vs the real button **Reset All
   Card Sizes** (home_devices.js:64 vs options_profile.js:26 and
   `qml/OptionStatusCards.qml:26`); "wires" used in user Help where the
   glossary's core term for what the user edits is **binding**/**action**
   (home_devices.js:273, 332, 364, 368, 385); "minimized" option name
   repeated with two links to the same topic (options_profile.js:44).

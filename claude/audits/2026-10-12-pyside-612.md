# PySide6 6.12 study (to-do 39), 2026-10-12, agent PYSIDE (read-only)

CI run 37754952665 (PySide6/Qt 6.12.0, commit 2c790ea0): 24 errored tests from 4 program launches + 2 menu wording failures.

## Cause 1, menus (very likely; from Qt docs + our code, not run on 6.12)
Qt 6.12 Menu gained `separatorsCollapsible` (default on): Qt sets separators' visible/height itself unless bound. Our theme/Gremlin/Menus/ThemedMenu.qml compactNow() sets the same properties by hand; a closed menu's rows read not-visible, so Qt hides separators we meant to show. Matches test_menus (missing "-" after Save Profile) and test_button_map_window ("Device, Close" instead of "---, Close").
Fix options: require 6.12 and drop our separator handling, or set separatorsCollapsible=false when the property exists.

## Cause 2, crash (candidates, not verified; no native trace in the logs)
Three of four crashed launches open the Keyboard page (test_j07_keyboard_page, test_handson_F4_shell, handson_F6_look_smoke; usability_smoke unconfirmed).
A: Qt 6.12 errors on missing required properties (InputConfiguration.qml:284-285 index/modelData; DialogHistory.qml:233-234, 374-377 entryId/when/areaName/title -> fits "History did not open").
B: PySide6 6.12 lifetime/ownership changes (PYSIDE-3469, -3374, -3423); nothing points at our paths.

## Recommendation
Stay pinned (<6.12; poetry.lock on 6.11.2; CI reads the lock since 4c7aa01e). A 6.12 trial needs the user's approval to download ~200 MB into a throwaway venv, then run the 3 crashing files with PYTHONFAULTHANDLER=1 and qt.qml logging, and the 2 menu tests with/without separatorsCollapsible.

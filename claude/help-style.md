# Help house style (D-01-ONE-HELP, 2026-10-09)

How every Help topic is written. Drawn from the patterns of well-regarded help
systems (Microsoft Writing Style Guide, Apple help books, Google developer
documentation style guide). The words for things on screen come from
`claude/glossary.md`.

## Voice

- Talk to the reader as **you**. Never "the user", "we", "our" or "I"
  (except in a Common questions title, which keeps the reader's own words:
  "How do I…?").
- Present tense, active voice: "Copy puts the setup on the stick", not "The
  setup will be put on the stick by Copy".
- Steps use the imperative: "Select a device, then choose **Rename…**".
- Plain, calm and professional. Short sentences. One idea per sentence.
- No filler: "simply", "just", "easily", "please", "note that", "basically".
- No blame or alarm: "To take back a change, choose **Undo**", not "If you
  made a mistake…". No exclamation marks.
- No internal words: spec or decision codes (S12, D-10-…), file or code names,
  "bug", "fix", "to-do", test or developer terms.
- Sentence case for topic titles; on-screen labels keep their own case.

## Topic types and titles

- **Task** topics say how to do something. Title starts with a verb:
  "Rename a device", "Undo a change", "Copy a setup to another stick".
- **Concept** topics say what something is, briefly. Title is a noun phrase:
  "Saved setups", "Modes".
- **Reference** topics list menus, keys or settings: "Device Library menus",
  "Keyboard keys".
- **Common questions** (one section per chapter): the question in the
  reader's words, a short answer, then a link to the full topic.

## Shape of a topic

1. One sentence that says what it's for (or what the thing is).
2. Numbered steps when the order matters; bullets otherwise. One action per
   step.
3. "Good to know": short notes at the end (limits, what is kept, how to take it
   back).
4. **Related topics**: links to 1–4 other topics (title as written).

Keep a topic to one screen where possible; split long topics.

## Formatting

- On-screen words in **bold**, spelled exactly as on screen (the guide tests
  check this): **Edit › Undo**, **Remove from Library…**.
- Keys in bold with "+": **Ctrl+Z**, **Shift+F10**, **F1**.
- Menu paths with "›": **Tools › History**.
- Quoted messages in straight double quotes, exactly as the program shows
  them.
- Numbers as digits; units spelled out ("10 saved setups", "0.5 seconds").

## One book

- Each subject is written **once**, in its chapter. Elsewhere, link to it.
- Chapters: Getting started · Home and devices · Configuration and actions ·
  Logical Device · OSC · Modes · Button Map · Device Library · Tools · Options and
  profile.
